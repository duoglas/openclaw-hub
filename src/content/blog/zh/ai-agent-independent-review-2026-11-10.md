## 背景

在 AI 内容生产中，质量是关键问题。单模型生成内容容易出现模板化、缺乏数据支撑、推断过度等问题。

我们设计了**独立审稿机制**：让两个不同的模型分别负责起草和审稿，通过交叉验证提高内容质量。

## 架构设计

```
WRITER（Astra） → 初稿 → REVIEWER（Luna） → 通过/拒绝 → 修改/发布
```

### 模型选择

| 角色 | 模型 | 特点 |
|---|---|---|
| WRITER | gpt-6-astra | 生成能力强，适合起草 |
| REVIEWER | gpt-6-luna | 判断严谨，适合审稿 |

### 审稿流程

1. WRITER 生成初稿
2. REVIEWER 独立审稿
3. 如果拒绝，WRITER 根据反馈修改
4. 最多 3 轮迭代

## 审稿提示词

### REVIEWER 提示词

```
你是独立审稿人，负责审核 AI 生成的新闻内容。

审稿标准：
1. 每个主张必须有原文支持
2. 拒绝未经证实的推断
3. 拒绝泛化建议（缺乏具体数据）
4. 接受单个支持良好的事件报道

拒绝理由必须具体，指出问题所在。
```

### WRITER 提示词

```
你是 AI 新闻编辑，需要根据提供的搜索结果生成日报。

写作要求：
1. 每条新闻必须包含具体数据（收入、用户数、日期、版本号）
2. 覆盖多个维度（产品、市场、政策）
3. 每段含事实/影响/行业背景对比
4. 禁止泛化建议，每条建议必须有原文支持
```

## 拒绝率分析

### 拒绝原因分布

| 原因 | 占比 | 说明 |
|---|---|---|
| 日期幻觉 | 35% | 模型推断的日期无原文支持 |
| 未证实推断 | 30% | 因果关系的推断缺乏原文支持 |
| 泛化建议 | 25% | 建议缺乏具体数据支撑 |
| 结构问题 | 10% | 内容结构不符合要求 |

### 迭代轮次分布

| 轮次 | 占比 | 说明 |
|---|---|---|
| 1 轮通过 | 40% | 初稿即通过 |
| 2 轮通过 | 35% | 修改 1 次后通过 |
| 3 轮通过 | 20% | 修改 2 次后通过 |
| 3 轮未通过 | 5% | 多次修改仍未通过 |

## 核心经验

### 经验 1：双模型交叉验证有效

Astra 负责生成，Luna 负责审稿，不同模型的判断标准不同，交叉验证能拦截 60% 的低质量输出。

### 经验 2：拒绝理由必须具体

REVIEWER 的拒绝理由越具体，WRITER 的修改越有效。泛化的拒绝理由（如"质量不够"）没有价值。

### 经验 3：限制迭代轮次

最多 3 轮迭代，避免无限循环。如果 3 轮后仍未通过，可以考虑降级处理或直接发布。

### 经验 4：保留拒绝记录

每次拒绝都有 reason 字段，这些记录可以帮助优化提示词和检测系统性问题。

## 质量控制指标

### 质量评分

| 指标 | 评分标准 |
|---|---|
| 数据密度 | 每条新闻至少 1 个具体数据点 |
| 来源多样性 | 至少 2 个不同来源 |
| 日期准确性 | 所有日期都有原文支持 |
| 建议合理性 | 每条建议都有原文支持 |

### 通过标准

- 数据密度 >= 1
- 来源多样性 >= 2
- 日期准确率 = 100%
- 建议合理性 = 100%

## 后续改进

1. **动态拒绝阈值**：根据历史通过率调整拒绝标准
2. **自动分类拒绝**：自动分类拒绝原因，便于分析
3. **质量趋势追踪**：追踪质量指标的变化趋势
